# Quickstart

Fifteen minutes, three files: a backend route that creates the charge, a backend route that reads
the status, and a mount call.

## Install

::: code-group

```bash [pnpm]
pnpm add @nanquim/core
pnpm add @nanquim/react            # optional
pnpm add @nanquim/abacatepay  # optional, if your PSP is AbacatePay
pnpm add @nanquim/server           # backend only
```

```html [CDN]
<script src="https://unpkg.com/@nanquim/core/dist/nanquim.global.js"></script>
<!-- exposes window.Nanquim -->
```

:::

Requirements: Node 24+ on the server, ESM only. In the browser: any environment with
`crypto.randomUUID` or `crypto.getRandomValues` — the SDK refuses to run without a cryptographic
random source rather than falling back to `Math.random()`.

## 1. Reserve the container's height

This is a hard requirement, not a nicety. The SDK renders its skeleton synchronously on mount,
but mount happens after the first paint — without a reservation, the merchant's page grows and
the layout shift is the *merchant's* Core Web Vital.

```css
#checkout { min-block-size: 620px; }
@media (min-width: 560px) { #checkout { min-block-size: 420px; } }
```

Measured on the reference integration: **0.0021 CLS with the reservation, 0.0193 without it.**

## 2. Create the charge on your backend

The route holds the PSP key. The browser never sees it.

```ts
// app/api/checkout/route.ts
import { idempotencyKey } from '@nanquim/server/verify';

export const runtime = 'nodejs';

export async function POST(request: Request): Promise<Response> {
  const key = process.env.ABACATEPAY_API_KEY;
  if (key === undefined) return Response.json({ error: 'missing key' }, { status: 500 });

  const response = await fetch('https://api.abacatepay.com/v1/pixQrCode/create', {
    method: 'POST',
    headers: {
      authorization: `Bearer ${key}`,
      'content-type': 'application/json',
      // pass the SDK's key through; generate one only if the caller sent none
      'idempotency-key': request.headers.get('idempotency-key') ?? idempotencyKey(),
    },
    // AbacatePay takes the amount in cents and expiresIn in seconds
    body: JSON.stringify({ amount: 12_990, expiresIn: 900 }),
    signal: AbortSignal.timeout(10_000),
  });

  if (!response.ok) return Response.json({ error: 'CREATE_FAILED' }, { status: 502 });

  // whitelist: never forward the PSP payload as-is
  const raw = await response.json();
  return Response.json(raw, { headers: { 'cache-control': 'no-store' } });
}
```

::: warning The idempotency key is generated by the SDK, honoured by you
`createSession` receives a CSPRNG-generated `idempotencyKey`, and it is **reused** when the payer
retries after a failure — exactly when a duplicate charge is possible. The SDK cannot deduplicate
anything; only your backend (or the PSP, if you forward the header) can. See
[The backend contract](/guide/backend#idempotency).
:::

## 3. Read the status on your backend

```ts
// app/api/checkout/[id]/status/route.ts
export async function GET(request: Request, { params }): Promise<Response> {
  const { id } = await params;
  if (!callerOwnsSession(request, id)) {
    return Response.json({ error: 'NOT_FOUND' }, { status: 404 });
  }
  // ...fetch from the PSP, parse, whitelist, return { status }
}
```

Proving ownership is not optional — see
[the status endpoint](/guide/backend#the-status-endpoint-must-prove-ownership).

## 4. Mount

```ts
import { createCheckout, pix } from '@nanquim/core';

const checkout = createCheckout({
  provider: pix(),
  locale: 'pt-BR',
  charge: { amount: 12_990, currency: 'BRL' },

  createSession: ({ signal, idempotencyKey }) =>
    fetch('/api/checkout', {
      method: 'POST',
      signal,
      headers: { 'idempotency-key': idempotencyKey },
    }).then((r) => r.json()),

  getStatus: ({ signal, session }) =>
    fetch(`/api/checkout/${session.sessionId}/status`, { signal }).then((r) => r.json()),

  onPaymentIndicated: ({ sessionId }) => confirmOnServer(sessionId),
  onDegraded: ({ reason }) => console.warn('[checkout]', reason),
  onError: (error) => report(error.code, error.message),
});

checkout.mount('#checkout');
void checkout.start();
```

`charge` is optional but recommended: it turns the promised price into an invariant. If the
created charge disagrees, the SDK fails with
[`amount_mismatch`](/reference/errors#amount-mismatch) instead of quietly drawing another price.

## 5. Ship the no-JS fallback

If JavaScript is off or the SDK fails to load, the page still has to say how to pay:

```html
<div id="checkout">
  <noscript>
    <p>Pay with Pix — copy the code below into your bank app:</p>
    <code>00020101021226…5204000053039865802BR…6304ABCD</code>
  </noscript>
</div>
```

In a server-created integration the payload is already on the server, so there is nothing to
fetch. This is verified in `e2e/audit.spec.ts`.

## 6. Verify the webhook

Payment is only true when the signed webhook says so.

```ts
import { handleWebhook } from '@nanquim/server';

const result = await handleWebhook({
  rawBody: await request.text(),
  signature: request.headers.get('x-signature') ?? '',
  timestamp: Number(request.headers.get('x-timestamp')),
  secret: process.env.WEBHOOK_SIGNING_SECRET!,
  store: seenStore,
  process: async (event) => {
    if (event.data.status.toUpperCase() === 'PAID') await creditOrder(event.data.id);
  },
});
```

The header names above are the SDK's default scheme: a hex HMAC-SHA256 over `timestamp.rawBody`.
**Your PSP almost certainly names its headers something else** — AbacatePay, for one, uses a
`?webhookSecret=` query parameter plus a base64 `X-Webhook-Signature` over the raw body with no
timestamp. Map it once, at the edge:
[AbacatePay's webhook scheme, and how to bridge it](/reference/provider#the-webhook-is-a-different-scheme-read-this-before-wiring-it).

Full contract: [`@nanquim/server`](/reference/server).

## Run the examples

```bash
pnpm install
pnpm build
node examples/vanilla-cdn/server.mjs   # http://localhost:4321
```

The vanilla example starts a fake merchant backend: it holds the "PSP key", creates a charge with
a BR Code that is structurally valid and checksum-correct over a fictional key, and marks it paid
after 12 seconds (`PAYS_AFTER_MS=0` to leave it pending).
